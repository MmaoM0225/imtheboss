## 1. 这份管什么

玩家在店里只做一件事：**把东西放到空地上**。放下去就开工，不要再派工、不要再点确认营业。

可放的分三类：**机位（含单人/双人/四人/五人）、内墙、设施**。

包不是房间，是更大一号的桌子。2 人包就是 2×2，五人包就是 3×3，全部和单人位挤在同一张大厅里。

外设墙算设施，不是单独系统。

---

## 2. 店面长什么样

格子、门、前台、开局两台机位的坐标，全部以 `docs/地图设计案.md` 为准。

开局只有 A（二楼）。另外三块怎么买归扩展案；买下来的空地，摆法仍按本案。

---

## 3. 能放什么

种类、占格、朝向、上限、贴墙，全部以 `docs/摆放物品设计案.md` 为准。

可放的分三类：**机位、内墙、设施**。员工不占格。同一格不能叠两件实体。

客人走到机位邻接的空地坐下。店门要能走到该机位邻接的至少 1 格空地。

---

## 4. 怎么放

平时不是建造状态。店在自己赚钱。

**R1 进入建造**  
点下半屏「布置」→ 列表按三类切页：机位 / 墙 / 设施 → 只显示已解锁且未到上限的 → 选一件 → 出现影子。

**R2 放下**  
点合法格 → 扣钱 → 落地 → 立刻生效 → 退出建造。  
例外：钱不够，按钮灰；不合法，影子红，不扣钱。

**R3 什么叫合法**

同时满足：

1. 完全落在空地上，不叠外墙、前台、别的实体
2. 不堵住店门（门前至少留 1 格空地）
3. 空调、外设墙必须有一条边贴外墙或内墙
4. 放下去之后，店门仍能走到 **每一块机位邻接的至少 1 格空地**
5. 没超过该种类上限；放机位时还没超过总座位 20

走不到就不让放。不要等客人卡住再报错。

**R4 取消建造**  
点返回，影子消失，不扣钱。一次只放一件。

---

## 5. 挪和卖

**R5 进整理**  
点「整理」→ 可点场上物件。点双人包/四人包/五人包是点整块桌子。

**R6 移动**  
机位 / 内墙 / 设施：变影子，再点合法格，不另扣钱。双人包、四人包、五人包整块移。  
例外：这块机位上任一座位坐着客人，不能移这整块。内墙若移完导致某块机位走不到，落点不合法。

**R7 卖掉**  
退买入价的 50%。机位、内墙、设施都是单独卖。前台不能卖。开局 2 台单人位可以卖。  
例外：有客人坐着的机位不能卖。

原地升级（换更好的电脑）不走摆放流程，占格和座位数不变。单人位不能升级成双人包或五人包——要卖了再买对应尺寸。

## 6. 数据字段

存档只记场上有哪些件。占地格不落盘，放/挪/卖之后按地图案 + 物品案重算。

### 物件实例（存档一行）

| 字段 | 类型 | 说明 |
|---|---|---|
| `uid` | string | 主键，如 `p_1` |
| `itemId` | 物品案的 id | 查种类 |
| `blockId` | `A` `B` `C` `D` | 在哪块地 |
| `col` | int | 锚点列（西南角） |
| `row` | int | 锚点行 |
| `rot` | `0` 横 / `1` 竖 | 不转的种类必须 0 |

不存：占格列表、座位列表、是否贴墙。上限：同 `itemId` 按物品案 `capScope` 计数。座位：该块所有 `seats` 之和，和地图案该块 `seatCap` 比。

开局两台的 `itemId/blockId/col/row/rot` 见地图案；`uid` 开局生成。

### 店存档（本案管的部分）

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | int | 从 `1` 起 |
| `nextUid` | int | 下一个实例号 |
| `items` | 上面的实例[] | 场上全部物件 |

`ownedBlocks`、`streetDoorBlock` 归扩展案。第一刀不存钱、天数、档次、客人。

### 运行时格（不存档）

每块一张内场表，大小 `interiorCols × interiorRows`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `col` `row` | int | |
| `placeable` | bool | 空地且无物件 |
| `walkable` | bool | 空地才能走 |
| `occupantUid` | string\|null | 占着这格的实例 |
| `occupantItemId` | id\|null | `inner_wall` 则贴墙算墙 |

R3 读这张表：完全落在 `placeable`；门前格至少 1 个 `walkable`；`needWall` 的占格四邻碰到 `outer_wall` 或 `inner_wall`；每块机位至少 1 个四邻 `walkable` 且从门前能 BFS 走到。BFS 只走内场 `walkable`，第一刀不跨块。

## 7. 和「放好就不管」的关系

- 单人位、双人包、四人包、五人包放下自己接待，不用点开机，不用进房间。
- 墙只在放置那一下挡路，过了就不要玩家管交通。
- 外设墙放下全店体验升高，不用给每个座位再插耳机。
- 没有「用墙围出包间」的解谜。

点某个座位看这一路账，点整块双人包/四人包/五人包看这一块总账，都是查看，归收益案。

---

## 8. 不做

- 不给座位单独挂耳机/键鼠/音箱/副屏，外设墙只是设施列表里的一件
- 不在一块空地里盖夹层、不做独立内室；买一楼/隔壁归扩展案
- 包不带门、不带围墙、不进单独战斗地图
- 不用内墙自动识别成包
- 不让玩家画过道、铺地板作为玩法
- 不做设施半径
- 不把网管、客人当成可摆物件
- 不在建造模式里暂停赚钱（时间照走，影子只是预览）
- 存档里不写二维地图；座位不拆成独立实体
- 不在实例上存 `buyPrice`、`grade`、`guestIds`

## 9. 给邻案的接口

| 邻案 | 本案给什么 |
|---|---|
| 地图设计案 | 空地上按本案判定能不能放；楼梯口/过道/门/前台不能摆 |
| 摆放物品设计案 | 用它的占格、朝向、上限、贴墙做合法判定 |
| 店面扩展案 | 每块空地按本案规则摆；店门以扩展案当前指定为准 |
| 收益案 | 每块机位是单人/双人/四人/五人；场上有哪些设施 |
| 客人与员工案 | 放下去之后哪些格被挡、每块机位的邻接空地 |
| 气泡事件案 | 座位上可以冒泡 |
